# 哈希表

**组别**：S　**关键词**：哈希函数、哈希冲突、拉链法、开放寻址法、unordered_map、随机权值哈希、集合哈希

## 1. 是什么 / 解决什么问题

如果要统计每个数出现了几次，数的范围是 $[1, 10^6]$ 时直接开桶 `cnt[x]++` 即可。但如果数的范围是 $10^{18}$、或者键是字符串、坐标对、整个棋盘状态，就开不下桶了。

**哈希表**的想法：用一个**哈希函数** $h$ 把很大的键压缩到 $[0, P)$ 的小范围里，再用这个小下标去开桶。好的哈希函数让不同的键尽量落在不同的桶里，于是插入、查找的期望时间都是 $O(1)$。

和它功能相近的是 `map`（红黑树，$O(\log n)$，有序）和"排序 + 离散化 + 二分"（离线，$O(\log n)$）。哈希表最快，但无序、最坏情况会退化。

## 2. 核心原理

### 2.1 哈希函数

整数最常用的是取模：$h(x) = x \bmod P$，$P$ 取一个和数据规模相当的**质数**。取质数是为了避免数据有规律时（例如全是 1000 的倍数）大量挤进少数几个桶。负数取模要写成 `(x % P + P) % P`。

字符串、数组等可以先转成一个整数（见"字符串哈希"），再取模。

### 2.2 冲突

不同的键可能算出相同的 $h$ 值，这叫**冲突**。由于键的种类远多于桶数，冲突不可避免，只能处理：

**拉链法**：每个桶挂一条链表，存所有落在这个桶里的键。查找时只在对应的链里找。

```text
P = 7，插入 3, 10, 17, 5
桶 0: -
桶 3: 17 -> 10 -> 3      （3、10、17 模 7 都是 3）
桶 5: 5
```

**开放寻址法**（线性探测）：桶里只存一个键；如果目标桶被别的键占了，就往后找下一个空桶。查找时从 $h(x)$ 开始往后找，遇到 $x$ 就是找到了，遇到空桶就说明不存在。

**负载因子** $\alpha = \dfrac{\text{元素个数}}{\text{桶数}}$。拉链法的期望链长就是 $\alpha$；开放寻址要求 $\alpha < 1$，一般让桶数是元素个数的 2 倍以上，否则探测会很长。

## 3. 代码模板

### 3.1 拉链法

和图的邻接表（链式前向星）写法完全一样：`head[u]` 是桶 $u$ 的第一个结点，`nxt[i]` 是下一个。

```cpp
const int N = 1e6 + 5, P = 1e6 + 3;
int n, q, tot;
int head[P], nxt[N], key[N], cnt[N];

inline int h(int x) { return (x % P + P) % P; }

void add(int x) {
    int u = h(x);
    for (int i = head[u]; i; i = nxt[i])
        if (key[i] == x) {
            cnt[i]++;
            return;
        }
    key[++tot] = x, cnt[tot] = 1, nxt[tot] = head[u], head[u] = tot;
}

int ask(int x) {
    for (int i = head[h(x)]; i; i = nxt[i])
        if (key[i] == x) return cnt[i];
    return 0;
}

void solve() {
    cin >> n >> q;
    For(i, 1, n) {
        int x;
        cin >> x;
        add(x);
    }
    while (q--) {
        int x;
        cin >> x;
        cout << ask(x) << endl;
    }
}
```

### 3.2 开放寻址法

```cpp
const int P = 2e6 + 3;
int n, q;
int key[P], cnt[P];
bool used[P];

int pos(int x) {
    int u = (x % P + P) % P;
    while (used[u] && key[u] != x) u = (u + 1) % P;
    return u;
}

void solve() {
    cin >> n >> q;
    For(i, 1, n) {
        int x;
        cin >> x;
        int u = pos(x);
        used[u] = 1, key[u] = x, cnt[u]++;
    }
    while (q--) {
        int x;
        cin >> x;
        int u = pos(x);
        cout << (used[u] ? cnt[u] : 0) << endl;
    }
}
```

`pos(x)` 返回 $x$ 所在的位置，或者 $x$ 应该插入的空位置。开放寻址只用几个连续数组，常数很小；缺点是不方便删除（直接清空会截断后面元素的探测链）。

### 3.3 STL：unordered_map / unordered_set

| 容器 | 实现 | 单次操作 | 有序 |
| --- | --- | --- | --- |
| `map` / `set` | 红黑树 | $O(\log n)$ | 是 |
| `unordered_map` / `unordered_set` | 哈希表（拉链） | 期望 $O(1)$ | 否 |

用法和 `map` 基本相同：`mp[x]++`、`mp.count(x)`、`mp.find(x)`、`mp.erase(x)`。

几个实用点：

- **提前 `reserve`**：`mp.reserve(n * 2);` 避免插入过程中反复扩容重建，常数能小很多。
- **键是 pair 等类型**时，STL 没有默认的哈希函数。最简单的办法是**编码成一个整数**：坐标 $x, y \in [0, 10^9]$ 时用 $x \cdot (2 \times 10^9 + 11) + y$，不会重复也不会溢出 64 位。
- **自定义哈希函数**：默认的整数哈希就是 $h(x) = x$，可以被专门构造的数据卡成每次 $O(n)$（在 Codeforces 等允许 hack 的比赛中常见）。可以换成 splitmix64 这类打乱函数。CSP 数据是固定的，一般不会专门卡，但了解一下没坏处。

下面统计 $n$ 个点中坐标完全相同的点对数：

```cpp
int n, ans;
struct hs {
    ull operator()(ull x) const {
        x += 0x9e3779b97f4a7c15ULL;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return x ^ (x >> 31);
    }
};
unordered_map<int, int, hs> mp;

void solve() {
    cin >> n;
    mp.reserve(n * 2);
    For(i, 1, n) {
        int x, y;
        cin >> x >> y;
        ans += mp[x * 2000000011LL + y]++;
    }
    cout << ans;
}
```

`ans += mp[key]++` 的含义：当前点能和之前每个相同的点配对，先加上之前的个数，再把计数加 1。

## 4. 随机权值哈希（集合哈希）

哈希不只能用来"查找"，还能把一个复杂对象**压缩成一个数**，用比较数代替比较对象。

问题：多次询问序列 $a$ 的区间 $[l_1, r_1]$ 和序列 $b$ 的区间 $[l_2, r_2]$ **作为多重集是否相同**（元素和出现次数都相同，不管顺序）。

做法：给每个值 $v$ 随机一个 64 位权值 $w_v$，一个多重集的哈希值定义为**所有元素的权值之和**（对 $2^{64}$ 自然溢出）。

- 两个多重集相同 ⇒ 和一定相同；
- 两个多重集不同 ⇒ 和相同的概率约为 $2^{-64}$，可以忽略。

求和可以前缀和相减，于是每次询问 $O(1)$。

```cpp
const int N = 2e5 + 5, V = 1e6 + 5;
int n, q;
ull w[V], sa[N], sb[N];
mt19937_64 rng(time(0));

void solve() {
    cin >> n >> q;
    Rep(i, 1, V) w[i] = rng();
    For(i, 1, n) {
        int x;
        cin >> x;
        sa[i] = sa[i - 1] + w[x];
    }
    For(i, 1, n) {
        int x;
        cin >> x;
        sb[i] = sb[i - 1] + w[x];
    }
    while (q--) {
        int l1, r1, l2, r2;
        cin >> l1 >> r1 >> l2 >> r2;
        cout << (sa[r1] - sa[l1 - 1] == sb[r2] - sb[l2 - 1] ? "YES" : "NO") << endl;
    }
}
```

变体：

- **异或哈希**：权值异或起来。异或时出现两次的元素会抵消，所以适合判断"每个值都出现偶数次"，**不能**用来判断多重集相等。
- **判断区间是否是 $1 \sim len$ 的排列**：区间权值和是否等于 $w_1 + \dots + w_{len}$。
- **按组维护**：把"每个点出度都为 1"转化为"所有边的起点权值之和等于所有点的权值之和"，修改时只需加减权值（CSP-S 2022 星战）。

随机数用 `mt19937_64`。不要用 `rand()`：在 Windows 下它最大只有 32767，冲突概率高得多。

## 5. 复杂度

| 实现 | 插入/查找 | 空间 |
| --- | --- | --- |
| 拉链法 / 开放寻址 | 期望 $O(1)$，最坏 $O(n)$ | $O(n + P)$ |
| `unordered_map` | 期望 $O(1)$，常数较大 | $O(n)$，内存开销大 |
| `map` | $O(\log n)$ | $O(n)$ |

`unordered_map` 实测常比手写慢好几倍，$10^6$ 级别、操作很多时优先手写或者离散化。

## 6. 常见题型与技巧

- **计数 / 去重**：值域很大的出现次数统计、不重复的数、字符串去重。
- **配对计数**：$A - B = C$ 的数对数：统计每个数出现次数，对每个 $a$ 查 $a - C$ 的次数。
- **状态判重**：BFS 搜索时把棋盘、排列编码成一个整数，放进哈希表判断是否访问过。
- **按复合键分组**：把几个关键信息拼成一个字符串或整数作为键，相同键的归为一组单独处理。
- **集合哈希**：多重集相等、区间是否为排列、图的度数条件判断，用随机权值求和。
- **哈希表 vs 离散化**：如果所有键能提前读入（离线），排序 + 去重 + `lower_bound` 往往更快更稳。

## 7. 易错点

- 负数取模要调整成非负：`(x % P + P) % P`。
- 用 `mp[x]` 查询会**自动插入**一个值为 0 的元素，大量查询时表会变大；只查询时用 `count` 或 `find`。
- 开放寻址的桶数要明显大于元素数；探测越过数组末尾时要回绕到开头（取模）。
- 多组数据清空：手写哈希表 `mset(head, 0)` 若 $P$ 很大且组数很多会超时，可以只清空用过的桶。
- 哈希值相等不代表一定相同（随机哈希有极小概率误判），但哈希值不等一定不同。
- 编码复合键时，确认不同的组合不会编码成同一个数（基数要大于另一维的范围），也不会溢出。
