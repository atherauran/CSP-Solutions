# 贪心

**组别**：J　**关键词**：贪心、交换论证、区间调度、区间选点、区间覆盖、邻项交换、哈夫曼、反悔贪心

## 1. 是什么 / 解决什么问题

贪心是一种做决策的策略：**每一步都选当前看起来最好的选项，选了就不再回头**。它通常写起来很短（排个序、扫一遍），难点全在"这样选为什么是对的"。

先看一个贪心成立的例子：找零钱，面额有 1、5、10、50、100 元，要凑出 $x$ 元且张数最少。每次都拿不超过剩余金额的最大面额，结果就是最优的。

再看一个不成立的例子：面额只有 1、3、4 元，凑 6 元。贪心先拿 4，再拿 1、1，共 3 张；但 3 + 3 只要 2 张。局部最优并不总能导出全局最优。

所以贪心题的一般流程是：

1. 想出一个"看起来对"的选择规则；
2. 用小例子（或者暴力程序）找反例；
3. 找不到反例时，尝试证明它；
4. 实在不对，就要考虑动态规划等其他方法。

贪心和动态规划的区别：动态规划考虑每一步的**所有**选择，用子问题的结果比较；贪心每一步只走**一个**选择。贪心能用的前提是"做出贪心选择后，剩下的问题仍能取到最优，且不比别的选择差"。

## 2. 核心原理：怎么证明贪心

### 2.1 交换论证

最常用的方法。假设有一个最优解与贪心解不同，找到第一个不同的地方，把最优解在那里的选择**换成**贪心的选择，证明：

1. 换完之后仍然合法；
2. 换完之后结果不变差。

于是最优解可以一步步变成贪心解而不变差，说明贪心解也是最优的。

**例：排队接水。** $n$ 个人接水，第 $i$ 个人要 $t_i$ 分钟，求一个顺序使所有人的等待时间之和最小。

排在第 $k$ 位的人的接水时间会让后面 $n - k$ 个人都多等这么久，所以总等待时间是 $\sum_k (n - k) \cdot t_{(k)}$，其中 $t_{(k)}$ 是排在第 $k$ 位的人的用时。如果某个相邻位置上 $t_{(k)} > t_{(k+1)}$，交换他们，总和变化为

$$(n-k) t_{(k+1)} + (n-k-1) t_{(k)} - (n-k) t_{(k)} - (n-k-1) t_{(k+1)} = t_{(k+1)} - t_{(k)} < 0,$$

变小了。所以最优顺序里不存在这样的相邻逆序，即**按用时从小到大排**。

### 2.2 保持领先（归纳法）

证明"贪心在每一步都不落后于任何解"，归纳到最后就说明贪心不比最优解差。下面区间调度的证明就是这个思路。

### 2.3 找反例

证明之前先找反例：手造几个极端的小数据（全相等、一个特别大、长短交错），或者写一个暴力枚举程序和贪心对比随机小数据。考场上时间有限，严格证明做不出时，能通过大量对拍也是相当可靠的依据。

## 3. 常见模型

### 3.1 区间调度：选最多的不相交区间

给 $n$ 个区间（如活动的开始、结束时间），选尽量多的两两不相交的区间。

**贪心：按右端点从小到大排序，能选就选。**

直觉：选一个结束最早的活动，给后面留下的时间最多。

证明（保持领先）：设贪心选出的区间右端点依次为 $g_1 < g_2 < \cdots$，任一合法方案的右端点依次为 $o_1 < o_2 < \cdots$。归纳证明 $g_k \le o_k$：$k = 1$ 时贪心选的就是右端点最小的区间；若 $g_{k-1} \le o_{k-1}$，则方案中第 $k$ 个区间的左端点在 $o_{k-1}$ 之后，也就在 $g_{k-1}$ 之后，贪心在第 $k$ 步至少可以选它，所以 $g_k \le o_k$。因此方案能选 $m$ 个时，贪心也至少能选 $m$ 个。

几个**错误**的规则和反例（区间都是左闭右开）：

| 规则 | 反例 | 贪心结果 | 最优 |
| --- | --- | --- | --- |
| 按左端点排序 | $[1, 10), [2, 3), [4, 5)$ | 选 $[1, 10)$，1 个 | 2 个 |
| 先选最短的 | $[1, 5), [4, 7), [6, 10)$ | 选 $[4, 7)$，1 个 | 2 个 |

### 3.2 区间选点

在数轴上放最少的点，使每个区间里至少有一个点。

**贪心：按右端点排序，如果当前区间里还没有点，就在它的右端点放一个点。**

放在右端点，是因为这个区间必须有点，而放在最右边能尽可能多地照顾到后面的区间。

有趣的是，区间选点的最少点数**等于**最多不相交区间数：贪心每放一个点，都对应一个"之前的点都不在里面"的区间，这些区间两两不相交，所以点数不超过最多不相交区间数；反过来，两两不相交的区间各自需要一个不同的点。两个问题的代码几乎一样。

### 3.3 区间覆盖

用最少的区间覆盖线段 $[s, t]$。

**贪心：按左端点排序。设当前已经覆盖到 $cur$（初始 $cur = s$），在所有左端点 $\le cur$ 的区间中，选右端点最大的那个，把 $cur$ 更新为这个右端点；重复直到 $cur \ge t$。** 如果某一步找不到能让 $cur$ 前进的区间，就无解。

为什么对：下一个选的区间必须包含点 $cur$（否则会留下空隙），在这些候选里，右端点越大，剩下要覆盖的部分越短，显然不会更差。

如果题目覆盖的是整数点（区间 $[1, 3]$ 和 $[4, 6]$ 算连上了），把条件改成"左端点 $\le cur + 1$"，初始 $cur = s - 1$。

### 3.4 邻项交换：排序规则怎么推

很多题要求给元素排一个顺序，使某个目标最优，但排序依据不明显。方法是：**只看相邻的两个元素 $i$ 和 $i + 1$，比较它们交换前后的结果**。交换相邻两项通常不影响其他元素，于是可以推出"$i$ 应排在 $i+1$ 前面"的条件，把它写成比较函数排序即可。

**例 1：拼数。** 把若干个正整数拼成一个最大的数。直觉"按字典序从大到小"是错的：$3$ 和 $30$ 按字典序 $30$ 在前得到 $303$，但 $330$ 更大。看相邻两项 $x, y$：它们拼在一起是 $x + y$ 或 $y + x$（字符串拼接），其他部分不变，所以 $x$ 应在前当且仅当 $x + y > y + x$。

**例 2：国王游戏。** 每个大臣左手 $a_i$、右手 $b_i$，大臣得到的金币是"排在他前面所有人（含国王）左手数之积"除以他自己的右手数。要让得金币最多的大臣得到的尽量少。

设 $i$ 和 $i + 1$ 前面所有人左手之积为 $P$。

| 顺序 | $i$ 得到 | $i+1$ 得到 |
| --- | --- | --- |
| $i$ 在前 | $P / b_i$ | $P a_i / b_{i+1}$ |
| $i+1$ 在前 | $P a_{i+1} / b_i$ | $P / b_{i+1}$ |

注意 $P a_i / b_{i+1} \ge P / b_{i+1}$，$P a_{i+1} / b_i \ge P / b_i$，所以两种顺序的最大值分别由 $P a_i / b_{i+1}$ 和 $P a_{i+1} / b_i$ 决定。$i$ 在前不更差 ⇔ $a_i / b_{i+1} \le a_{i+1} / b_i$ ⇔ $a_i b_i \le a_{i+1} b_{i+1}$。所以按 $a_i b_i$ 从小到大排即可。

**为什么相邻交换就够了？** 任何排列都能通过"交换相邻逆序对"（冒泡排序）变成排好序的样子，每次交换都不让答案变差，所以排好序的顺序不比任何顺序差。前提是推出的比较规则满足传递性（是一个合法的排序关键字），像 $a_i b_i$ 这样能写成单个数值的关键字自然没问题；如果比较规则写不成单一关键字，要小心它是否真的能用来排序。

### 3.5 哈夫曼思想：每次合并最小的两个

**合并果子**：$n$ 堆果子，每次合并两堆，代价是两堆重量之和，求合并成一堆的最小总代价。

**贪心：每次取最小的两堆合并。**

把合并过程画成一棵二叉树，叶子是原始的堆，每堆的重量被计入代价的次数等于它的深度，总代价 $= \sum a_i \cdot dep_i$。要让总和最小，重量越小的应该越深；最小的两堆一定可以放在最深的一层且互为兄弟（交换论证），也就是第一步合并它们。合并后把新堆看成一个叶子，问题规模减 1，归纳即可。这正是**哈夫曼树**的构造方法。

实现用小根堆，$O(n \log n)$。如果重量范围小或者已经排好序，可以用两个队列做到 $O(n)$：一个队列放排好序的原始堆，另一个放合并出来的新堆。合并出来的新堆重量是单调不降的，所以两个队列都有序，每次从两个队首里取较小的即可。

### 3.6 反悔贪心

有时候当前的最优选择后来可能会被证明是错的。**反悔贪心**的思路是：先贪心地选上，同时把选过的东西存进堆里；后面发现更好的选择时，从堆里"撤销"一个最差的。

**例：带截止时间的任务。** $n$ 个任务，每个耗时 1 个单位，任务 $i$ 必须在时刻 $d_i$ 之前（含）完成，完成可得收益 $p_i$。求最大总收益。

按截止时间从小到大处理，每个任务先选上（收益放进小根堆）。若选上后堆的大小超过当前截止时间 $d_i$，说明这么多任务在 $d_i$ 之前做不完，就丢掉收益最小的那个。

为什么对：处理完截止时间 $\le d$ 的所有任务后，最多只能做其中 $d$ 个，而只要选出的任务满足"截止时间 $\le d$ 的不超过 $d$ 个"对每个 $d$ 都成立，就一定能排出合法顺序（按截止时间依次做）。在这个限制下保留收益最大的那些显然最优，堆正好维护了这一点。

类似的还有"建筑抢修"：任务耗时不同，求最多完成几个。按截止时间排序，累计用时，超时就扔掉耗时最长的那个（用大根堆）。

### 3.7 其他常见形式

- **按位贪心**：求最大的异或、与、或时，从高位到低位尝试让这一位为 1，因为高位的 1 比所有低位加起来都大。
- **用之前最便宜的**：加油、买入问题中，每一段需求都用"此前见过的最便宜价格"满足，扫描时维护前缀最小值。
- **构造最小/最大数**：先让位数最优，再从高位到低位逐位放最小/最大的可行数字。
- **田忌赛马式配对**：两组数排序后用双指针匹配。

## 4. 代码模板

**区间调度**：比赛时间为 $[l, r)$，一个比赛结束后可以立刻开始下一个，最多参加几个。区间选点只需把判断改成 `a[i].l > last`（闭区间、点放在 `a[i].r`）。

```cpp
const int N = 1e6 + 5;
int n, ans, last = -LINF;
struct seg { int l, r; } a[N];

bool cmp(const seg &a, const seg &b) {
    return a.r < b.r;
}

void solve() {
    cin >> n;
    For(i, 1, n) cin >> a[i].l >> a[i].r;
    sort(a + 1, a + 1 + n, cmp);
    For(i, 1, n)
        if (a[i].l >= last) ans++, last = a[i].r;
    cout << ans;
}
```

**区间覆盖**：用最少的区间覆盖 $[s, t]$，无解输出 $-1$。

```cpp
const int N = 1e5 + 5;
int n, s, t, ans;
struct seg { int l, r; } a[N];

bool cmp(const seg &a, const seg &b) {
    return a.l < b.l;
}

void solve() {
    cin >> n >> s >> t;
    For(i, 1, n) cin >> a[i].l >> a[i].r;
    sort(a + 1, a + 1 + n, cmp);
    int cur = s, j = 1;
    while (cur < t) {
        int r = cur;
        while (j <= n && a[j].l <= cur) r = max(r, a[j++].r);
        if (r == cur) {
            cout << -1;
            return;
        }
        cur = r, ans++;
    }
    cout << ans;
}
```

**邻项交换（拼数）**：

```cpp
const int N = 25;
int n;
string a[N];

bool cmp(const string &a, const string &b) {
    return a + b > b + a;
}

void solve() {
    cin >> n;
    For(i, 1, n) cin >> a[i];
    sort(a + 1, a + 1 + n, cmp);
    For(i, 1, n) cout << a[i];
}
```

**合并果子（哈夫曼）**：

```cpp
int n, ans;
priority_queue<int, vector<int>, greater<int>> q;

void solve() {
    cin >> n;
    For(i, 1, n) {
        int x;
        cin >> x;
        q.push(x);
    }
    while (q.size() > 1) {
        int x = q.top();
        q.pop();
        int y = q.top();
        q.pop();
        ans += x + y, q.push(x + y);
    }
    cout << ans;
}
```

**反悔贪心（带截止时间的任务）**：

```cpp
const int N = 1e5 + 5;
int n, ans;
struct job { int d, p; } a[N];
priority_queue<int, vector<int>, greater<int>> q;

bool cmp(const job &a, const job &b) {
    return a.d < b.d;
}

void solve() {
    cin >> n;
    For(i, 1, n) cin >> a[i].d >> a[i].p;
    sort(a + 1, a + 1 + n, cmp);
    For(i, 1, n) {
        q.push(a[i].p), ans += a[i].p;
        if ((int)q.size() > a[i].d) ans -= q.top(), q.pop();
    }
    cout << ans;
}
```

## 5. 复杂度

贪心本身通常是一次线性扫描，复杂度主要来自排序或堆：

- 排序 + 扫描：$O(n \log n)$；
- 堆维护（合并果子、反悔贪心）：$O(n \log n)$；
- 区间覆盖的双指针部分：$j$ 只增不减，扫描 $O(n)$；
- 按位贪心：$O(n \cdot \text{位数})$。

## 6. 常见题型与技巧

1. **看到"最多选几个""最少用几个"且对象是区间**，先想 3.1～3.3 的三个区间模型，注意题目是开区间还是闭区间、端点相接算不算相交。
2. **看到"安排顺序使某个值最优"**，试试邻项交换推排序规则。
3. **看到"每次合并两个，代价是和"**，想哈夫曼。
4. **贪心选了之后可能后悔**，想反悔贪心：堆里存已选的，必要时弹出最差的。
5. **贪心作为子过程**：二分答案的检验函数里经常是一个贪心（如"能否在 $T$ 天内完成"），见《二分查找与二分答案》。
6. **先贪心、再修正**：先让每个人都选最优，再处理违反限制的部分，并让修正的代价最小（CSP-S 2025 社团招新）。
7. **不确定时写暴力对比**：贪心最容易"看起来对"，几十组随机小数据就能发现大部分错误。

## 7. 易错点

- **没有验证就交**：找零钱、"先选最短区间"这类直觉都可能是错的。至少手造几组反例试一试。
- **排序关键字选错**：区间调度按右端点，区间覆盖按左端点，不要混。
- **端点处理**：闭区间 $[1, 3]$ 和 $[3, 5]$ 相交，左闭右开 $[1, 3)$ 和 $[3, 5)$ 不相交，代码里是 `>` 还是 `>=` 要对应。
- **比较函数相等时返回 `true`**：`return a + b >= b + a;` 会导致 `sort` 出错。
- **比较规则不满足传递性**：邻项交换推出的规则如果不能化成单一关键字，直接排序可能得到错误结果。
- **溢出**：合并果子类问题总代价可能很大；国王游戏的乘积需要高精度。
- **区间覆盖无解没判**：找不到能延伸的区间时要及时退出，否则死循环。
- **堆的方向**：`priority_queue` 默认是大根堆，小根堆要写 `greater<int>`。
