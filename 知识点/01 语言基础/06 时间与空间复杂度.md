# 时间与空间复杂度

**组别**：J　**关键词**：大 O 记号、时间复杂度、空间复杂度、数据范围、均摊分析、主定理、递归树

## 1. 是什么 / 解决什么问题

写代码之前要先回答：这个做法会不会超时、会不会超内存？**复杂度**就是用来回答这个问题的工具。它不关心程序在某台机器上具体跑几毫秒，而是描述"数据规模 $n$ 变大时，运算次数（或内存）以什么速度增长"。

有了复杂度，就能：

- 拿到题目后根据数据范围**反推**需要什么级别的算法；
- 比较两种做法的优劣；
- 设计部分分：$n \le 1000$ 的点用 $O(n^2)$ 暴力，满分用 $O(n \log n)$。

## 2. 时间复杂度

### 2.1 数运算次数

```text
For(i, 1, n) For(j, 1, n) s += a[i] * a[j];
```

内层语句执行 $n^2$ 次，每次是常数次操作，所以总运算量约 $c \cdot n^2$。$n$ 翻倍时运行时间变成 4 倍。

### 2.2 大 O 记号

若存在常数 $c$，使得 $n$ 足够大时运算次数 $T(n) \le c \cdot f(n)$，就记作 $T(n) = O(f(n))$，读作"复杂度是 $f(n)$ 级别"。实际使用时只保留**增长最快的项**，并去掉**常数系数**：

- $3n^2 + 100n + 7 = O(n^2)$；
- $\frac{n(n-1)}{2} = O(n^2)$；
- $5 = O(1)$；
- $\log_2 n$ 与 $\log_{10} n$ 只差常数倍，统一写 $O(\log n)$。

为什么可以忽略低次项：$n = 10^5$ 时 $n^2 = 10^{10}$，而 $100n = 10^7$，后者可以忽略不计。

常见复杂度从小到大：

$$O(1) < O(\log n) < O(\sqrt{n}) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$$

### 2.3 常见代码结构的复杂度

| 代码结构 | 复杂度 | 说明 |
| --- | --- | --- |
| 单层循环 $1 \sim n$ | $O(n)$ | |
| 两层循环，`j` 从 1 到 `i` | $O(n^2)$ | $1 + 2 + \dots + n = \frac{n(n+1)}{2}$ |
| 每次 `n /= 2` 直到 0 | $O(\log n)$ | 约 $\log_2 n$ 次 |
| `i * i <= n` | $O(\sqrt{n})$ | 试除法判质数、分解因数 |
| `For(i, 1, n)` 内套 `for (j = i; j <= n; j += i)` | $O(n \log n)$ | 调和级数 $\frac{n}{1} + \frac{n}{2} + \dots + \frac{n}{n} \approx n \ln n$ |
| 排序 | $O(n \log n)$ | |
| 二分查找 / 堆 / `set` 单次操作 | $O(\log n)$ | |
| 枚举所有子集 | $O(2^n)$ | |
| 枚举所有排列 | $O(n!)$ | |

可以写一段程序直接数一数：

```cpp
int n, c1, c2, c3, c4;

void solve() {
    cin >> n;
    For(i, 1, n) For(j, 1, i) c1++;
    for (int x = n; x > 0; x /= 2) c2++;
    For(i, 1, n) for (int j = i; j <= n; j += i) c3++;
    for (int i = 1; i * i <= n; i++) c4++;
    cout << c1 << " " << c2 << " " << c3 << " " << c4 << endl;
}
```

$n = 1000$ 时输出 `500500 10 7069 31`，分别对应 $\frac{n(n+1)}{2}$、$\log_2 n$、$n \ln n \approx 6908$、$\sqrt{n}$。

### 2.4 调和级数的例子

求 $1 \sim n$ 每个数的约数个数。对每个 $i$，枚举它的倍数 $j$，给 $d_j$ 加 1：

```cpp
const int N = 1e6 + 5;
int n;
int d[N];

void solve() {
    cin >> n;
    For(i, 1, n) for (int j = i; j <= n; j += i) d[j]++;
    For(i, 1, n) cout << d[i] << " ";
    cout << endl;
}
```

$n = 12$ 输出 `1 2 2 3 2 4 2 4 3 4 2 6`。总次数 $\sum_{i=1}^{n} \lfloor n / i \rfloor \approx n \ln n$，$n = 10^6$ 时约 $1.4 \times 10^7$。如果对每个数单独试除求约数，是 $O(n \sqrt{n}) = 10^9$，慢得多。"枚举倍数"是数论题中非常常用的技巧（埃氏筛也是这个思路）。

### 2.5 均摊分析

有些代码看起来是两层循环，实际却是 $O(n)$。例：给定 $n$ 个正整数，求和不超过 $S$ 的连续子段个数（双指针）。

```cpp
const int N = 1e5 + 5;
int n, s, ans, sum;
int a[N];

void solve() {
    cin >> n >> s;
    For(i, 1, n) cin >> a[i];
    int l = 1;
    For(r, 1, n) {
        sum += a[r];
        while (sum > s) sum -= a[l++];
        ans += r - l + 1;
    }
    cout << ans << endl;
}
```

输入 `5 5` 和 `1 2 3 4 5`，符合条件的子段有 $[1], [2], [3], [4], [5], [1,2], [2,3]$，输出 `7`。

`while` 循环在某一次 $r$ 中可能执行很多次，但 $l$ 只增不减，**总共**最多增加 $n$ 次。所以整个程序的 `while` 总执行次数 $\le n$，复杂度 $O(n)$。这种"把总代价摊到所有操作上"的分析叫**均摊分析**。单调栈、单调队列、`vector::push_back` 的复杂度都是这样分析的。

### 2.6 递归的复杂度

递归程序的复杂度用**递推式**描述，最直观的求法是画**递归树**：每个结点代表一次调用，结点上写这次调用自身（不含子调用）的工作量，总复杂度就是所有结点之和。

| 递推式 | 例子 | 结果 |
| --- | --- | --- |
| $T(n) = T(n/2) + O(1)$ | 二分查找、快速幂 | $O(\log n)$ |
| $T(n) = T(n-1) + O(1)$ | 递归求阶乘 | $O(n)$ |
| $T(n) = 2T(n/2) + O(1)$ | 递归求区间最大值 | $O(n)$ |
| $T(n) = 2T(n/2) + O(n)$ | 归并排序 | $O(n \log n)$ |
| $T(n) = T(n-1) + O(n)$ | 选择排序 | $O(n^2)$ |
| $T(n) = 2T(n-1) + O(1)$ | 汉诺塔、递归枚举子集 | $O(2^n)$ |

以归并排序 $T(n) = 2T(n/2) + O(n)$ 为例：

```text
第 0 层：1 个规模 n 的问题，合并代价 n            合计 n
第 1 层：2 个规模 n/2 的问题，每个合并代价 n/2    合计 n
第 2 层：4 个规模 n/4 的问题，每个代价 n/4        合计 n
...
共 log n 层                                        总计 n log n
```

**主定理的直觉**：对 $T(n) = aT(n/b) + f(n)$，比较"叶子总数" $n^{\log_b a}$ 和"根的工作量" $f(n)$：

- 若 $f(n)$ 明显更小，每层工作量往下越来越多，叶子占主导，$T(n) = O(n^{\log_b a})$。例：$T(n) = 2T(n/2) + O(1)$，$n^{\log_2 2} = n$，结果 $O(n)$。
- 若二者同阶，每层工作量差不多，乘上层数，$T(n) = O(f(n) \log n)$。例：归并排序。
- 若 $f(n)$ 明显更大，每层越来越少，根占主导，$T(n) = O(f(n))$。例：$T(n) = 2T(n/2) + O(n^2)$，结果 $O(n^2)$。

## 3. 数据范围与复杂度对照

评测机每秒大约能执行 $10^8 \sim 10^9$ 次简单运算。为了稳妥，估算时把运算量控制在 **$10^8$ 左右**。1 秒时限下的常见对应：

| 数据范围 $n$ | 可接受的复杂度 | 典型算法 |
| --- | --- | --- |
| $\le 10$ | $O(n!)$ | 全排列枚举、搜索 |
| $\le 20$ | $O(2^n \cdot n)$ | 子集枚举、状压 DP |
| $\le 40$ | $O(2^{n/2})$ | 折半搜索 |
| $\le 100 \sim 500$ | $O(n^3)$ | Floyd、区间 DP |
| $\le 2000 \sim 5000$ | $O(n^2)$ | 二维 DP、枚举两端点 |
| $\le 10^5 \sim 10^6$ | $O(n \log n)$ | 排序、二分、堆、线段树、树状数组 |
| $\le 10^7$ | $O(n)$ | 前缀和、双指针、线性筛、单调队列 |
| $\ge 10^9$ | $O(\sqrt{n})$、$O(\log n)$、$O(1)$ | 数学公式、试除、快速幂、二分 |

使用这张表的方法是**反推**：看到 $n \le 2 \times 10^5$，就知道要找 $O(n \log n)$ 或 $O(n)$ 的做法；看到 $n \le 20$，多半是指数级枚举。题目的部分分档位也往往对应不同复杂度的做法。

估算时还要考虑**常数**：

- 简单数组操作常数很小；`map`、`set`、`unordered_map` 常数大，$10^6$ 次操作可能需要数百毫秒。
- 取模、除法比加法、乘法慢数倍。
- 按行访问二维数组比按列访问快很多（缓存友好）。
- 多组数据时，复杂度要乘上组数（除非题目保证 $\sum n$ 有上限）。

## 4. 空间复杂度

程序使用的内存主要来自**数组**、**容器**和**递归栈**。估算方法：元素个数 × 每个元素的字节数。

| 类型 | 字节 |
| --- | --- |
| `char`、`bool` | 1 |
| `int32_t` | 4 |
| `long long`、`double`（以及本仓库模板中的 `int`） | 8 |
| `pair<int, int>`（模板下） | 16 |

$1\text{MB} = 2^{20} \approx 10^6$ 字节。例：

- `int a[1000000]`（模板下 64 位）：$8 \times 10^6$ 字节 $\approx 8$MB；
- `int f[5000][5000]`：$8 \times 2.5 \times 10^7 = 2 \times 10^8$ 字节 $\approx 191$MB，256MB 限制下很危险；
- `int32_t to[2000000][26]`：$4 \times 5.2 \times 10^7 \approx 198$MB；若用 64 位则翻倍，必然超限。

减少空间的常用方法：

- **滚动数组**：DP 只依赖上一行时，只开两行 `f[2][M]`；
- **大数组改用 32 位**：值不超过 $2^{31}$ 的大数组声明为 `int32_t`；
- `bool`、`char` 数组代替整数数组存 0/1；
- 递归深度 × 栈帧大小也是空间，深度 $10^6$ 时要注意。

有些环境下没被写入的全局数组不计入内存，但不要依赖这一点，一律按申请的大小估算。

## 5. 常见题型与技巧

- **看数据范围选算法**：先估最大运算量，确定目标复杂度，再去想对应的算法。
- **算清楚最坏情况**：如 [CSP-J 2022 T1 乘方](#/P8813)，$a = 1$ 时循环 $b = 10^9$ 次会超时，要特判。
- **询问多、修改少**时，可以让修改慢一些、询问快一些，按"次数 × 单次代价"分别估算（[CSP-J 2021 T2 插入排序](#/P7910)）。
- **均摊**：指针单调移动的双指针、单调栈，总复杂度按指针移动总次数算。
- **空间要算到 MB**：大数组按字节估算，必要时用 32 位类型（[CSP-S 2023 T2 消消乐](#/P9753)、[CSP-S 2019 D2T2 划分](#/P5665)）。

## 6. 易错点

- 只看循环层数：`while` 里指针单调移动时可能是均摊 $O(n)$，而一层循环里调用了 $O(n)$ 的函数（如 `strlen(s)`、`s.substr`、`v.erase(v.begin())`、`memset` 整个数组）则是 $O(n^2)$。
- 把 `strlen(s)` 写在 `for` 的条件里，每次循环都重新计算长度。
- 函数参数传 `vector`、`string` 不加引用，每次调用都复制。
- 多组数据每组都 `memset` 大数组：总代价是组数 × 数组大小。
- 忽略 STL 的常数，$10^7$ 次 `map` 操作必然超时。
- 空间按 32 位估算，却在模板（`int` 为 64 位）下开数组，实际翻倍。
- $O(n \log n)$ 中的 $\log$ 以 2 为底，$n = 10^6$ 时 $\log_2 n \approx 20$，不是 6。
