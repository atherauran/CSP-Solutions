# 进制与编码

**组别**：J　**关键词**：进制转换、位权、二进制、十六进制、原码、反码、补码、浮点数

## 1. 是什么 / 解决什么问题

我们平时写的 $1234$ 是**十进制**：每一位上的数字乘上"这一位的权重"再相加，$1234 = 1\times10^3 + 2\times10^2 + 3\times10 + 4$。把 10 换成任意整数 $k \ge 2$，就得到 **$k$ 进制**。计算机内部只认 0 和 1，所以所有整数、小数、字符最终都要**编码**成二进制。

这一块在 CSP 里的作用：

- **初赛**几乎每年必考：进制互转、补码表示、表示范围、浮点数精度、ASCII、存储单位换算。
- **复赛**里是基本功：二进制拆分（位运算、状态压缩）、按位处理、`unsigned long long` 的范围与溢出、浮点误差。

## 2. 核心原理

### 2.1 位权展开：$k$ 进制 → 十进制

$k$ 进制数 $(d_{m-1} d_{m-2} \cdots d_1 d_0)_k$（每位 $0 \le d_i < k$）的值是

$$\sum_{i=0}^{m-1} d_i \cdot k^i$$

$k^i$ 叫第 $i$ 位的**位权**。超过 9 的数码用字母表示：A=10，B=11，…，F=15（十六进制）。

例：$(2\text{F})_{16} = 2\times16 + 15 = 47$；$(1011)_2 = 8 + 0 + 2 + 1 = 11$。

编程时不必算幂，用**秦九韶算法**（霍纳法则）从高位往低位扫：

$$x \gets x \cdot k + d_i$$

$(1011)_2$：$0 \to 1 \to 2 \to 5 \to 11$。每多读一位，原来的数整体左移一位（乘 $k$），再加上新的最低位。

### 2.2 除 $k$ 取余：十进制整数 → $k$ 进制

设 $x = (d_{m-1}\cdots d_1 d_0)_k$，则

$$x = k \cdot (d_{m-1}\cdots d_1)_k + d_0$$

所以 $x \bmod k = d_0$ 就是**最低位**，$\lfloor x/k \rfloor$ 是去掉最低位后剩下的数。不断"取余、整除"，依次得到 $d_0, d_1, \dots$，最后**倒过来**输出。

例：$47$ 转二进制

| $x$ | $x \bmod 2$ | $\lfloor x/2\rfloor$ |
|---|---|---|
| 47 | 1 | 23 |
| 23 | 1 | 11 |
| 11 | 1 | 5 |
| 5 | 1 | 2 |
| 2 | 0 | 1 |
| 1 | 1 | 0 |

倒序读出：$(101111)_2$。

### 2.3 乘 $k$ 取整：十进制小数 → $k$ 进制

小数 $0.d_{-1}d_{-2}\cdots$ 乘 $k$ 后，整数部分正好是 $d_{-1}$，小数部分是剩下的 $0.d_{-2}\cdots$。所以不断"乘 $k$、取走整数部分"，**正序**得到各位。

例：$0.625$ 转二进制：$0.625\times2 = 1.25$ 取 1；$0.25\times2=0.5$ 取 0；$0.5\times2 = 1.0$ 取 1，结束。得 $(0.101)_2$。

$0.1$ 转二进制：$0.2\to0,\ 0.4\to0,\ 0.8\to0,\ 1.6\to1,\ 1.2\to1,\ 0.4\to0,\dots$ 出现循环，$0.1 = (0.0\overline{0011})_2$ 是**无限循环小数**。这就是计算机里 $0.1$ 不能被精确存储的原因。

一般地，十进制小数能有限地写成二进制，当且仅当它化成最简分数后分母是 2 的幂。

### 2.4 二、八、十六进制直接互转

$8 = 2^3$，$16 = 2^4$，所以 1 位八进制恰好对应 3 位二进制，1 位十六进制恰好对应 4 位二进制。从小数点向两边分组，不足的补 0：

```text
二进制      1  0111  1010 . 1100
十六进制    1    7     A  .   C        → (17A.C)_16
二进制     101 111 010 . 110
八进制      5   7   2  .  6            → (572.6)_8
```

要在八进制和十六进制之间转换，先展开成二进制再重新分组。$a$ 进制转 $b$ 进制的一般做法是**先转十进制再转 $b$ 进制**。

### 2.5 负进制（扩展）

基数也可以是负数，比如 $-2$ 进制：$(110)_{-2} = 1\times4 + 1\times(-2) + 0 = 2$。转换仍然是"除基取余"，但 C++ 中负数取余可能得到负余数。若 $x = q\cdot k + r$ 且 $r < 0$（$k<0$），改写成

$$x = (q+1)\cdot k + (r - k)$$

$r - k = r + |k| \in [0, |k|)$ 就是合法数码。

### 2.6 原码、反码、补码

用 $n$ 位二进制表示**有符号整数**。以 8 位为例：

| 真值 | 原码 | 反码 | 补码 |
|---|---|---|---|
| $+5$ | 0000 0101 | 0000 0101 | 0000 0101 |
| $-5$ | 1000 0101 | 1111 1010 | 1111 1011 |
| $+0$ | 0000 0000 | 0000 0000 | 0000 0000 |
| $-0$ | 1000 0000 | 1111 1111 | 0000 0000 |
| $-128$ | 无 | 无 | 1000 0000 |

- **原码**：最高位是符号位（0 正 1 负），其余是绝对值。
- **反码**：正数同原码；负数在原码基础上，符号位不变，其余位取反。
- **补码**：正数同原码；负数 = 反码 + 1。

**正数的三种码完全相同**，区别只在负数。

**为什么计算机用补码？** 关键是 $n$ 位运算天然是在模 $2^n$ 下进行的（最高位的进位直接丢掉）。对任意 $x$，$x$ 与按位取反 $\sim x$ 相加每一位都是 1：

$$x + \sim x = 2^n - 1 \quad\Longrightarrow\quad \sim x + 1 = 2^n - x \equiv -x \pmod{2^n}$$

所以"取反加一"得到的正是 $-x$ 在模 $2^n$ 意义下的代表。于是减法 $a - b$ 可以直接当作 $a + (\sim b + 1)$ 用加法器完成，符号位也不需要特殊处理。例如 $5 + (-5)$：`0000 0101 + 1111 1011 = 1 0000 0000`，丢掉第 9 位得 0。

补码的其他好处：$0$ 只有一种表示；$n$ 位补码表示范围是 $[-2^{n-1}, 2^{n-1}-1]$（比原码多一个 $-2^{n-1}$）。

| 类型 | 位数 | 范围 |
|---|---|---|
| `int` | 32 | $-2^{31} \sim 2^{31}-1$，约 $\pm 2.1\times10^9$ |
| `long long` | 64 | $-2^{63} \sim 2^{63}-1$，约 $\pm 9.2\times10^{18}$ |
| `unsigned long long` | 64 | $0 \sim 2^{64}-1$，约 $1.8\times10^{19}$ |

**溢出**：`int` 的 $2^{31}-1$ 再加 1，按补码会变成 $-2^{31}$（有符号溢出在 C++ 标准里是未定义行为，不要依赖它）；无符号类型的溢出是**定义好的**，就是模 $2^{64}$ 取余，哈希里常利用这一点。

补码还解释了一些位运算现象：`-1` 的补码是全 1；`x & -x` 取出最低位的 1（lowbit）；右移负数是算术右移（高位补 1）。

### 2.7 浮点数

浮点数就是二进制的"科学计数法"。IEEE 754 标准把一个数写成

$$(-1)^s \times 1.f \times 2^{e - \text{bias}}$$

| 类型 | 总位数 | 符号 $s$ | 阶码 $e$ | 尾数 $f$ | 有效数字（十进制） |
|---|---|---|---|---|---|
| `float` | 32 | 1 | 8（bias 127） | 23 | 约 6～7 位 |
| `double` | 64 | 1 | 11（bias 1023） | 52 | 约 15～16 位 |

例：$5.75 = (101.11)_2 = 1.0111 \times 2^2$，`float` 中 $s = 0$，$e = 2 + 127 = 129$，$f = 0111\,000\cdots$。

由此得到几个必须知道的结论：

- **有限位数，必有舍入误差**：$0.1 + 0.2 \ne 0.3$。比较两个浮点数要用 `fabs(a - b) < EPS`。
- `double` 的尾数只有 52 位（加隐含的 1 共 53 位），所以超过 $2^{53} \approx 9\times10^{15}$ 的整数就不能都精确表示。**大整数不要用 `double` 存**，`sqrt`、`pow` 的结果对大数也可能差 1，需要上下微调。
- 表示范围很大（`double` 约 $10^{\pm308}$），但精度有限：范围大 ≠ 精确。
- `long double` 在 GCC/x86 上通常是 80 位扩展精度，尾数 64 位，精度更高但更慢。

### 2.8 字符编码与存储单位

- **ASCII** 用 7 位（一个字节存）表示 128 个字符。常用：`'0'` = 48，`'A'` = 65，`'a'` = 97，空格 = 32，换行 `'\n'` = 10。所以 `c - '0'` 把数字字符变成数值，`c - 'a' + 'A'` 把小写变大写，大小写字母相差 32。
- **汉字编码**：GB2312/GBK 一个汉字 2 字节；UTF-8 中常用汉字 3 字节。
- **存储单位**：1 Byte = 8 bit；1 KB = 1024 B，1 MB = 1024 KB，1 GB = 1024 MB。`int` 4 字节，`long long`/`double` 8 字节，`char` 1 字节。估算内存：$10^7$ 个 `long long` 约 76 MB。

## 3. 代码模板

$k$ 进制字符串与十进制互转（$2 \le k \le 36$，数码用 `0-9A-Z`）：

```cpp
inline int val(char c) {
    if (c >= '0' && c <= '9') return c - '0';
    return c - 'A' + 10;
}

inline char dig(int x) {
    return x < 10 ? '0' + x : 'A' + x - 10;
}

int tod(string s, int k) {
    int x = 0;
    for (char c : s) x = x * k + val(c);
    return x;
}

string tok(int x, int k) {
    if (x == 0) return "0";
    string s;
    while (x) s += dig(x % k), x /= k;
    reverse(s.begin(), s.end());
    return s;
}
```

$a$ 进制转 $b$ 进制就是 `tok(tod(s, a), b)`。

十进制小数转 $k$ 进制，取前 `len` 位：

```cpp
string fra(double x, int k, int len) {
    string s = "0.";
    Rep(i, 0, len) {
        x *= k;
        int d = x;
        s += dig(d), x -= d;
    }
    return s;
}
```

负进制（基数 $k < 0$）：

```cpp
string neg(int x, int k) {
    if (x == 0) return "0";
    string s;
    while (x) {
        int r = x % k;
        x /= k;
        if (r < 0) r -= k, x++;
        s += dig(r);
    }
    reverse(s.begin(), s.end());
    return s;
}
```

查看一个数的补码可以用 `bitset`：

```cpp
void solve() {
    cout << bitset<8>(5) << endl;
    cout << bitset<8>(-5) << endl;
    cout << bitset<8>(-128) << endl;
}
```

输出 `00000101`、`11111011`、`10000000`。

## 4. 复杂度

- $k$ 进制转十进制：$O(\text{位数})$。
- 十进制 $x$ 转 $k$ 进制：位数为 $\lfloor\log_k x\rfloor + 1$，复杂度 $O(\log_k x)$。

## 5. 常见题型与技巧

1. **初赛进制计算**：先转成二进制再分组，比直接在十进制下算更快更不易错。例如 $(3\text{A})_{16} + (75)_8$：$(3\text{A})_{16} = (0011\,1010)_2$，$(75)_8 = (111\,101)_2$，二进制相加得 $(111\,0111)_2$，按 3 位、4 位分组读出 $(167)_8 = (77)_{16}$（十进制 $58 + 61 = 119$）。
2. **初赛补码题**：给出 8 位补码求真值——最高位为 1 时，"取反加一"得到绝对值。如 `1110 0110` → 取反 `0001 1001` → 加一 `0001 1010` = 26，真值 $-26$。
3. **二进制拆分**：任何正整数都能唯一写成若干个不同的 2 的幂之和（就是它的二进制表示）。用于"拆成 2 的幂"类题、倍增、二进制优化多重背包。
4. **按位独立**：异或、与、或都是逐位运算，常把问题拆到每一个二进制位分别考虑。
5. **处理 64 位边界**：数据达到 $2^{63}$ 以上要用 `unsigned long long`；$2^{64}$ 本身连 `unsigned long long` 都存不下，需要特判或用 `__int128`。
6. **大数开方**：`sqrt` 返回 `double`，对 $10^{18}$ 级别可能差 1。求 $\lfloor\sqrt x\rfloor$ 后用 `while (s * s > x) s--; while ((s + 1) * (s + 1) <= x) s++;` 修正。

## 6. 易错点

- 除 $k$ 取余得到的是**从低到高**的数位，输出前要倒序；$x = 0$ 要单独输出 `0`。
- 数码超过 9 要用字母；读入时注意题目给的是大写还是小写。
- `1 << 40` 中的 `1` 是 32 位的，会溢出；要写 `1LL << 40`。本仓库模板把 `int` 宏成了 `long long`，但**字面量 `1` 仍是 32 位**。
- `1ULL << 64` 是未定义行为，不是 0。
- C++ 中负数 `%` 的结果符号跟被除数相同：`-7 % 3 == -1`。需要非负余数时写 `(x % k + k) % k`。
- 浮点数不要用 `==` 比较；不要用 `double` 存需要精确的大整数。
- 反码、原码中 $0$ 有两种表示；8 位补码的范围是 $-128 \sim 127$，不是 $-127 \sim 127$。
